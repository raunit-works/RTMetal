# Performance audit — 2026-11-17

## Scope and method

- Production build (`npm run build`) served locally with `next start`: baseline on port 3011,
  post-optimisation check on port 3012.
- Staging Supabase project (`rbucefvtkiohmaugvkyz`).
- Four public routes: `/`, `/home-decor`, `/metal-coating`, `/home-decor/ashok-stambh-premium-decorative-showpiece`.
- Desktop 1440×900 and mobile 390×844, one empty-cache run per route.
- Lighthouse is **not installed**, so measurements use Chromium CDP network events plus
  `PerformanceObserver` (LCP, CLS, long tasks) and the Navigation Timing API.
- Raw data: `audit-2026-11-17-baseline.json`, `audit-2026-11-17-after-image.json`,
  `audit-2026-11-17.json` (final); repeat with `node reports/performance/measure.mjs`.
- Single-run, local-server numbers: compare relatively, not as field data. No CDN, image host
  optimisation edge, or real mobile network is included.

Approved change, limited to the public product-card image:

- `sizes` corrected from mobile `100vw` to `50vw` (the catalog is a 2-column grid on

## Findings

1. **Mobile Home Decor image payload was the main risk and is now improved.** 22 image requests total
   **2.04 MB** on `/home-decor` (2.56 MB total page transfer), more than double the
   desktop image payload. Home (`933 KB`) and Metal (`1.06 MB`) are also image-heavy.
   Catalog cards were the dominant cost, not JavaScript. The card `sizes`/quality fix cut
   mobile image bytes to **848 KB** (see the optimisation table).
2. **Home LCP is the slowest paint.** Desktop `/` LCP is **2.79 s** on the hero
   `img.object-cover`; every other route paints under 1.1 s. The home hero competes with
   video/font/image requests (7 media requests on home/collection routes).
3. **Product detail desktop downloads 729 KB of scripts across 34 requests**, versus
   ~275 KB on mobile. A desktop run also recorded 2 document responses; this likely
   reflects prefetch/preload duplication and should be re-checked against a deployed host
   and on repeat runs.
4. **Autoplay/streamed video.** Home, Home Decor and Metal routes each issue 7 partial
   (`206`) media requests. On mobile these are wasted bytes when the video is offscreen,
   paused, or replaced by a poster.
5. **Fonts.** Home desktop downloads 128 KB across 7 font files; other routes 67–114 KB.
6. **No layout instability or main-thread blocking in this run.** CLS is **0** on all
   routes and no long tasks (>50 ms) were observed. TTFB after the first cold request is
   0.5–0.9 s.
7. **Build hygiene warning:** `metadata.metadataBase` is unset, so Next falls back to
   `http://localhost:3000` while resolving social images. This is not a runtime
   performance issue but affects production metadata URLs.

## Recommended next steps

Priority order, pending approval:

1. ~~Reduce catalog image bytes on mobile with tighter `sizes`, lower quality and lazy
   loading.~~ **Done for product cards; re-measured at 848 KB images.** To reach ~500 KB,
   reduce the initial number of rendered cards or add an explicit initial batch.
2. Preload the Home hero image (`priority`/`fetchpriority="high"`) and serve a smaller
   mobile hero source; target LCP under 2.5 s.
3. Pause or replace background video on mobile until interaction; keep a poster image.
4. Re-run the audit against the deployed host/CDN and repeat each route 3× to separate
   warm/cold TTFB and confirm the product-detail script duplication.
5. Revisit font subsetting/weights if additional pages are added.
6. Set `metadataBase` in the root metadata (separate, non-performance cleanup).

The only performance change made is the product-card image `sizes`/`quality` update above.
No packages were installed and no other performance code was changed.
